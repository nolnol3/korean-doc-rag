# PDF·HWPX·이미지 문서 넣기

방법은 세 가지다. 어느 쪽이든 KorQuAD 평가용 색인과는 분리된 컬렉션(기본 `docs`)에 들어간다.

| 방법 | 언제 쓰나 |
|---|---|
| 화면의 "문서 넣기"에 파일을 끌어다 놓는다 | 몇 개만 넣고 바로 물어볼 때 |
| `POST /upload` (multipart `files[]`, `collection`) | 다른 시스템에서 연동할 때. 기존 청크는 그대로 두고 새 청크만 추가하며, 내용이 같은 청크는 다시 넣지 않는다 |
| `COLLECTION=docs python -m kdr.ingest_docs ./dir/` | 파일이 많을 때. 이 방식은 컬렉션을 처음부터 다시 만들기 때문에 지운 문서가 남지 않는다 |

받는 형식은 PDF, HWPX, 이미지(PNG·JPG·WEBP·TIFF·BMP)다. 스캔한 PDF와 이미지는 OCR로 읽는다.

질문할 때는 화면에서 컬렉션을 고르거나 API에 `{"collection": "docs"}`를 넣는다.

## 처리 방식

| 형식 | 처리 |
|---|---|
| PDF | 페이지마다 본문 블록을 읽어 청크로 묶는다(아래 "본문 청킹"). 괘선이 있는 표는 따로 찾아 markdown 표로 바꾸고, 표 하나를 청크 하나로 넣는다. 표 영역은 본문에서 제외한다 |
| HWPX | `Contents/section*.xml`의 문단(`hp:p`)을 읽는다. 표(`hp:tbl`)는 markdown 표로 바꾼다 |
| 스캔 PDF | 텍스트 레이어가 30자 미만이고 표도 없는 페이지는 스캔으로 보고, 200dpi로 렌더링해 OCR한다. 텍스트 레이어가 있는 페이지는 그대로 둔다 (더 정확하고 빠르다) |
| 이미지 | 파일 전체를 OCR한다. 인용 제목은 파일명 |

## 본문 청킹

표를 뺀 본문은 LangChain의 `RecursiveCharacterTextSplitter`로 묶는다. 구분자 우선순위는 `문단(\n\n)` → `줄(\n)` → `다. ` → `요. ` → `. ` → `공백` → `글자`이고, 상한 900자, 인접 청크는 100자(문장 단위로 반올림)만큼 겹친다. 짧은 문단은 상한까지 합쳐지고, 긴 문단은 문장이 끝나는 곳에서 잘린다. 기본 구분자에는 한국어 문장 경계가 없어 `다. `, `요. `를 넣었다. 청크는 페이지(PDF)·절(HWPX)을 넘지 않는다 — 인용 제목이 한 쪽을 가리켜야 하기 때문이다.

`.env`의 `CHUNK_SIZE`, `CHUNK_OVERLAP`으로 바꾼다. KorQuAD 컬렉션은 평가의 정답 단위가 문단이라 이 청킹을 거치지 않고 문단 그대로 색인한다.

청크마다 `source`(파일명), `page`(PDF는 쪽 번호, HWPX는 절 번호), `kind`(text, table, ocr) 메타데이터가 붙는다. 인용 제목은 "파일명 p.N" 형식으로 API 응답에 그대로 나온다.

## OCR

엔진은 [EasyOCR](https://github.com/JaidedAI/EasyOCR)(ko+en)이다. pip만으로 설치되고 torch를 임베딩 모델과 공유하므로 시스템 바이너리가 필요 없다. 첫 실행 때 인식 모델(약 100MB)을 `.easyocr/`에 내려받는다. Docker에서는 `hf-cache` 볼륨에 들어간다.

인식 결과는 단어 단위 상자로 나온다. `kdr.ocr.group_lines`가 y 좌표가 같은 줄 높이 안에 있는 상자를 한 줄로, 줄 간격이 줄 높이의 1.5배를 넘는 곳에서 문단으로 나눈다. 그 뒤는 PDF 본문과 같은 청킹을 거친다.

`.env`로 조절한다.

```
OCR_ENABLED=true     # false면 스캔 페이지·이미지는 빈 채로 남는다
OCR_LANGS=ko,en
OCR_DPI=200          # 페이지 렌더링 해상도. 작은 글씨가 깨지면 300
OCR_GPU=false        # CUDA에서만 true. Apple MPS는 easyocr이 지원하지 않는다
```

`easyocr`이 설치되어 있지 않으면(`uv pip install -e ".[dev]"`처럼 `ocr` extra를 뺀 경우) 경고를 남기고 해당 페이지를 건너뛴다. 다른 형식의 인제스트는 영향을 받지 않는다.

**확인한 범위.** `tests/fixtures/sample_report.pdf`를 300dpi 이미지로 바꾼 스캔 PDF와 PNG(`make fixtures`로 생성)를 올리고 4문항을 물었다. 본사 위치·임직원 수, 매출·영업이익, 정식 출시 시점, 부문별 매출 비중 모두 정답이었고 근거 검증도 통과했다. OCR 자체는 완벽하지 않다 — 회사명 "한빛테크"를 "한빛터크"로 읽었고, 150dpi 스캔에서는 "%"가 "9"로 읽혔다. 그래도 질문에 회사명이 들어간 문항이 맞은 것은 형태소 BM25와 임베딩이 한 글자 오차를 흡수하기 때문이다. CPU(Apple M 시리즈)에서 A4 한 쪽에 약 5초 걸린다.

```
Q: 5년 이상 근속하면 연차가 며칠인가?
A: 17일 [2]
   [2] sample_policy.hwpx §1  [표] | 근속연수 | 연차일수 | ... | 5년 이상 | 17일 |
   path: retrieve → grade:2/4 → generate → verify:ok
```

## 확인한 범위

표가 들어 있는 PDF·HWPX 샘플(`tests/fixtures/`)과 위키백과에서 내려받은 PDF 3건으로 11문항을 물어봤다. 10문항은 정답이었고, 문서에 답이 없는 1문항은 "근거를 찾지 못했다"고 답했다. 모델은 Qwen3 8B, 구성은 그래프 RAG다.

## 한계

- 괘선이 없는 표(위키백과 정보 상자 같은 것)는 표로 인식되지 않고 본문 텍스트로 들어간다. 답은 나오지만 표 구조는 잃는다. Docling이나 pymupdf_layout으로 바꾸면 나아질 것이다.
- PDF의 줄바꿈이 단어 중간에 남을 수 있다("증 권사이다"). 형태소 분석과 임베딩이 어느 정도 흡수하지만 완전하지는 않다.
- HWP 5.0(구형 바이너리 형식)은 지원하지 않는다. HWPX만 된다.
- OCR한 페이지의 표는 표로 인식되지 않고 본문 텍스트로 들어간다 (셀 값은 남지만 행·열 구조는 잃는다). 스캔 표의 구조까지 살리려면 PaddleOCR의 표 인식 모듈 같은 것이 필요하다.
- OCR 오인식은 그대로 색인된다. 회사명·고유명사처럼 한 글자가 틀리면 답에도 틀린 철자가 나올 수 있다.
- 텍스트 레이어가 조금이라도 있는 페이지(30자 이상)는 OCR하지 않는다. 텍스트 레이어가 깨진 PDF(글자가 □로 나오는 것)는 `OCR_MIN_CHARS`를 크게 잡거나 이미지로 변환해 올려야 한다.
- 여러 단으로 조판된 문서는 블록 순서가 섞일 수 있다.
