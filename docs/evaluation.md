# 평가

데이터: KorQuAD 1.0. train+dev의 위키 문단 10,639개를 코퍼스로, dev 질문에서 seed 고정 샘플. 답변은 KorQuAD 공식 정규화 규칙으로 EM/F1(문자 단위) 채점. 채점 전 우리 포맷인 `[n]` 인용 표시만 뗀다.

## 검색 방식 — recall@k, dev 1,000문항, LLM 호출 없음

| 방식 | R@1 | R@5 | R@10 |
|---|---|---|---|
| vector (bge-m3) | 0.707 | 0.892 | 0.920 |
| bm25 · 공백 분리 | 0.658 | 0.797 | 0.836 |
| bm25 · kiwi 형태소 | **0.850** | **0.956** | 0.977 |
| hybrid (RRF) | 0.786 | 0.952 | **0.979** |

- **형태소 분석의 몫이 R@5 +15.9pp.** 공백 분리는 "삼성전자의"와 "삼성전자"가 다른 토큰이라 조사 때문에 매칭이 깨진다. 형태소 분석이 없는 외산 플랫폼의 한국어 키워드 검색이 이 상태다.
- BM25가 벡터를 이기는 건 KorQuAD 특성 — 질문이 문단을 보고 작성돼 어휘가 겹친다. 실제 사용자 질문은 더 바꿔 말하므로 hybrid를 기본값으로 둔다.
- hybrid는 R@5에서 BM25와 동률, R@1은 뒤진다(RRF가 약한 벡터 순위를 섞음). LLM은 top-5를 보므로 실질 차이 없음.

## 발견

### 1. 검색 없이는 둘 다 모른다 — 차이는 모를 때의 행동

"강한 모델은 검색이 덜 필요하다"는 가설로 Claude 행을 넣었는데, 검색 없는 EM은 Claude 10.5%, Qwen3 3.5%로 둘 다 낮았다. 대신 Claude는 46.5%를 **기권**하고("모르겠습니다"), Qwen3는 1.5%만 기권하고 나머지를 지어낸다. 기권을 뺀 정답률은 Claude F1 0.46, Qwen3 0.26. 사내문서 QA에서 중요한 건 정답률만큼이나 모를 때 모른다고 하는가다.

### 2. 그래프의 이득은 재검색이 아니라 grade의 컨텍스트 선별

200문항 짝 비교: 그래프가 크게 나은 21건, 나쁜 8건, 동일 171건. 나아진 건 문서 5개 → 관련 1~2개로 줄여 7B가 엉뚱한 문단을 안 보게 된 경우. 나빠진 건 grade가 정답 문단을 버린 경우(정답 문단 포함 94.0 → 93.5%). 재검색이 살린 건 1건. **호출 7.4배에 +3.8pp** — 비용 대비 이득은 작다.

| 질문 | 단순 RAG | 그래프 |
|---|---|---|
| 한씨와 한 전 총리는 어디의 임대·임차인 관계인가? | 한명숙 | **지역구 사무실** |
| 구조와 현재 사이의 시간은 몇 년인가? | 약 70억 년 | **100억 년** |
| 평창 동계올림픽 주 개최지 선정 날짜 | **2002년 1월 9일** | 근거 못 찾음 — grade가 정답 문단을 버림 |

### 3. 한국어 키워드 검색은 형태소 분석이 결과의 절반을 좌우한다

위 ablation 표.

### 4. verify는 강한 모델이 맡아야 한다

Qwen3 verify는 그래프 오답 16건을 **전부** grounded=True로 통과시켰다. grounded 0.985는 "답이 근거 있음"이 아니라 "7B 검증자가 거르지 못함"이다. 같은 날 Claude verify는 "YYYY년 M월 D일 ○○ 사건을 주도한 혐의로 수배되었다"는 문장에 대해 *"그 날짜는 사건 날짜이지 수배 날짜가 아닐 수 있다"*고 판정했다 — KorQuAD 정답의 중의성을 잡아낸 것. 생성은 로컬, 판정은 API라는 구성의 근거.

## 실패 사례

- **대조군 오염** — "LLM만" 프롬프트에 "문서"라는 단어가 들어가자 7B가 200문항 중 182를 기권했다. 단어 하나가 대조군을 0점으로 만든다. 중립 프롬프트로 교체하고 전부 재실행.
- **채점 오염** — 답에 붙인 `[1]` 인용 표시가 EM을 깼다(0.005). 채점 전 제거 → 0.555. 문장형 답변도 F1을 눌러서 "정답만 명사구로" 프롬프트로 전 arm 재실행 → 0.695.
- **라벨 오류** — "○○이 이끈 정당의 명칭은?"의 정답이 정당명이 아니라 질문의 주어(인물명)로 적혀 있는 문항이 있다. 모델은 정당명을 맞게 답했고 0점. EM/F1은 하한선이다.
- **verify:fail 루프** — Claude가 중의적 문장을 계속 "근거 없음"으로 판정하며 재검색 → 같은 문서 → 같은 답 → 같은 판정(11호출). "새 근거가 없으면 정지" 규칙으로 5호출.
- **컨텍스트 창** — Ollama 기본 `num_ctx` 4096에 문서 5개 프롬프트(4,188토큰)가 잘리고 있었다. 8192로.

## 한계

- 태스크가 위키 QA다. 사내 문서의 권한·최신성은 다루지 않았다.
- KorQuAD는 질문이 문단과 어휘를 공유해 BM25에 유리하다.
- EM/F1은 하한선이다 — 라벨 오류, 형태 차이("Beyond The Scene" vs 뜻 설명)가 섞여 있다.
- 단일 시드 1회 실행. 문항별 짝 비교로 방향은 확인했지만 신뢰구간은 붙이지 않았다.

## 재현

```bash
make fetch && make index      # 약 10분 (Apple Silicon)
make ablation                 # LLM 호출 없음, 수 분
ollama pull qwen3:8b && make eval          # 로컬 8B 약 1시간
LLM_PROVIDER=openai make eval             # OpenAI 호환 엔드포인트로 같은 200문항
```

결과는 `results/{model}/{arm}.jsonl`(문항별)과 `summary.md`. `python -m kdr.eval --rescore results/qwen3-8b`로 저장된 답변을 다시 채점할 수 있다.
