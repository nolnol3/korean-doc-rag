# 평가

데이터는 KorQuAD 1.0이다. train과 dev에 있는 위키백과 문단 10,639개를 코퍼스로 쓰고, 질문은 dev에서 seed를 고정해 뽑았다. 답변은 KorQuAD 공식 정규화 규칙을 적용해 EM과 문자 단위 F1로 채점한다. 답에 붙은 `[n]` 인용 표시는 우리 쪽 형식이므로 채점 전에 뗀다.

## 검색 방식 비교

dev 1,000문항에 대해 정답 문단이 상위 k개 안에 들어오는 비율(recall@k)이다. LLM 호출은 없다.

| 방식 | R@1 | R@5 | R@10 |
|---|---|---|---|
| vector (bge-m3) | 0.707 | 0.892 | 0.920 |
| bm25, 공백 분리 | 0.658 | 0.797 | 0.836 |
| bm25, kiwi 형태소 분석 | 0.850 | 0.956 | 0.977 |
| hybrid (RRF) | 0.786 | 0.952 | 0.979 |
| hybrid + cross-encoder rerank | **0.932** | **0.986** | 0.987 |

- 형태소 분석을 하면 R@5가 15.9%p 오른다. 공백으로만 자르면 "삼성전자의"와 "삼성전자"가 다른 토큰이 되어 조사 때문에 매칭이 실패한다. 형태소 분석기가 없는 검색 플랫폼에서 한국어 키워드 검색이 이 상태가 된다.
- BM25가 벡터 검색보다 높게 나온 것은 KorQuAD의 특성이다. 질문이 문단을 보고 작성되어 어휘가 많이 겹친다. 실제 사용자는 문서와 다른 표현으로 질문하는 경우가 많으므로 기본값은 hybrid로 둔다.
- hybrid는 R@5에서 BM25와 같고 R@1에서는 뒤진다. RRF가 상대적으로 약한 벡터 순위를 섞어 넣기 때문이다. LLM에는 상위 5개를 주므로 실질적인 차이는 없다.
- reranker(bge-reranker-v2-m3)는 hybrid 상위 40개를 질문과 하나씩 대조해 다시 줄 세운다. R@1이 14.6%p 오르고 BM25 단독도 넘는다. 후보 40개 안에는 정답이 거의 다 있었으므로(R@10 0.979) 순서만 고친 효과다. R@10은 후보 폭에 막혀 더 오르지 않는다. 문항당 약 1초(MPS, fp16).

## 실험에서 확인한 것

### 1. 검색이 없으면 두 모델 다 답하지 못한다. 차이는 모를 때의 행동에 있다

"큰 모델은 검색이 덜 필요하다"는 가설을 확인하려고 Claude를 함께 돌렸다. 결과는 달랐다. 검색 없이 답한 EM은 Claude 10.5%, Qwen3 4.5%로 둘 다 낮았다. 대신 모를 때의 행동이 갈렸다. Claude는 46.5%를 "모르겠습니다"로 기권했고, Qwen3는 1.5%만 기권하고 나머지는 틀린 답을 냈다. 기권한 문항을 빼고 계산한 정답률은 Claude F1 0.46, Qwen3 0.27이다. 사내 문서 QA에서는 정답률만큼이나 모를 때 모른다고 하는지가 중요하다.

### 2. 그래프의 효과는 재검색이 아니라 grade의 문단 선별에서 나온다

200문항을 문항별로 비교하면 그래프 RAG가 단순 RAG보다 크게 나은 문항이 14개, 크게 나쁜 문항이 7개, 나머지 179개는 같다. 나아진 문항은 grade가 문단 5개 중 관련 있는 1~2개만 남겨서 7B 모델이 엉뚱한 문단을 보지 않게 된 경우다. 나빠진 문항은 grade가 정답 문단을 관련 없다고 판정해 버린 경우다(정답 문단 포함률 94.0% → 93.5%). 재검색(rewrite)까지 간 문항은 11개뿐이다. 호출은 7.4배 늘고 F1은 2.0%p 오른다. 비용 대비 효과는 크지 않다.

| 질문 | 단순 RAG | 그래프 RAG |
|---|---|---|
| 한씨와 한 전 총리는 어디의 임대·임차인 관계인가? | 한명숙 | 지역구 사무실 (정답) |
| 구조와 현재 사이의 시간은 몇 년인가? | 약 70억 년 | 100억 년 (정답) |
| 평창 동계올림픽 주 개최지 선정 날짜 | 2002년 1월 9일 (정답) | 근거를 찾지 못함. grade가 정답 문단을 버렸다 |

### 3. 한국어 키워드 검색은 형태소 분석에 크게 좌우된다

위 검색 방식 비교표 참고.

### 5. grade는 LLM보다 cross-encoder가 낫다 — 더 정확하고 5회 호출이 0회가 된다

2번에서 "그래프의 효과는 grade의 문단 선별에서 나온다"고 확인했으니, 그 선별을 LLM 대신 cross-encoder 점수로 해 봤다. dev 300문항으로 임계값을 잡았다. 정답 문단 점수는 중앙값 0.997, 무관 문단은 0.012로 갈리고, 0.2를 기준으로 하면 정답 문단의 97.9%를 남기고 무관 문단의 78.3%를 버린다.

결과는 표의 아래 두 행이다. 단순 RAG에 reranker만 붙여도 EM이 4.5%p 올라 기존 그래프 RAG를 넘는다. 그래프 RAG의 grade를 reranker로 바꾸면 F1이 가장 높고(0.874) grounded도 가장 높으면서 LLM 호출은 7.4→2.0회다. rewrite까지 간 문항이 11→5개, grade가 문단을 전부 버린 문항이 6→3개로 줄었다. 검색 단계가 좋아지니 재시도 루프 자체가 덜 돈다.

그래프+rerank의 EM이 단순+rerank보다 낮은(0.745 vs 0.765) 이유는 답의 형식이다. 두 팔이 갈린 22문항 중 그래프 쪽이 진 13문항은 대부분 "46명 중 13등"(정답 "13등"), "2012"(정답 "2012년"), "솔트레이크시티 외곽 할러데이"(정답 "할러데이")처럼 부분 점수는 받고 정확 일치만 놓친 경우다. grade가 문단을 1개만 남기면 모델이 그 문단을 더 길게 인용하는 경향이 보인다. 임계값이 정답 문단을 버린 경우는 2문항이다.

검색이 14.6%p 좋아졌는데 답변은 4.5%p만 오른 이유는, 원래도 정답 문단이 상위 5개 안에 있는 문항이 94%였기 때문이다. reranker가 고칠 수 있는 건 나머지 6%뿐이고, 정답 문단이 눈앞에 있어도 8B 모델이 잘못 읽는 오답은 검색으로는 줄지 않는다.

### 4. verify는 큰 모델에 맡겨야 한다

Qwen3의 verify는 그래프 RAG의 오답 17건을 전부 "근거 있음"으로 통과시켰다. grounded 0.985라는 수치는 답에 근거가 있다는 뜻이 아니라 7B 검증기가 아무것도 걸러내지 못했다는 뜻이다. 같은 날 Claude의 verify는 "YYYY년 M월 D일 ○○ 사건을 주도한 혐의로 수배되었다"는 문장에 대해 "그 날짜는 사건 날짜이지 수배 날짜가 아닐 수 있다"고 판정했다. KorQuAD 정답 자체의 중의성을 잡아낸 것이다. 생성은 로컬 모델이 하고 판정은 API 모델이 하는 구성의 근거가 된다.

## 실패 사례

- 대조군 프롬프트 오염. "LLM만" 구성의 프롬프트에 "문서"라는 단어가 들어가자 7B 모델이 200문항 중 182문항을 기권했다. 단어 하나가 대조군을 0점으로 만들었다. 중립적인 프롬프트로 바꾸고 전부 다시 실행했다.
- 채점 오염. 답에 붙인 `[1]` 인용 표시가 정확 일치(EM)를 깨뜨려 0.005가 나왔다. 채점 전에 떼자 0.555가 됐다. 문장으로 길게 답하는 것도 F1을 낮춰서, "정답만 명사구로" 쓰라는 프롬프트로 전 구성을 다시 실행했더니 0.720이 됐다.
- 라벨 오류. "○○이 이끈 정당의 명칭은?"이라는 문항의 정답이 정당명이 아니라 질문의 주어인 인물명으로 적혀 있다. 모델은 정당명을 맞게 답했지만 0점을 받았다. EM과 F1은 실제 정답률보다 낮게 나온다.
- verify 실패 반복. Claude가 중의적인 문장을 계속 "근거 없음"으로 판정하면서 재검색 → 같은 문단 → 같은 답 → 같은 판정을 반복해 11번을 호출했다. 재검색 결과가 이전과 같으면 멈추는 규칙을 넣어 5번으로 줄였다.
- 컨텍스트 창. Ollama의 기본 `num_ctx`가 4096인데 문단 5개를 넣은 프롬프트가 4,188토큰이어서 잘리고 있었다. 8192로 올렸다.

문항 단위 분석은 [`results/qwen3-8b/failures_naive.md`](../results/qwen3-8b/failures_naive.md)와 [`failures_graph.md`](../results/qwen3-8b/failures_graph.md)에 있다.

## 한계

- 위키백과 QA로 평가했다. 사내 문서에서 중요한 접근 권한과 최신성은 다루지 않았다.
- KorQuAD는 질문과 문단의 어휘가 겹쳐 BM25에 유리하다.
- EM과 F1은 실제 정답률보다 낮다. 라벨 오류와 표현 차이("Beyond The Scene"이라는 원어 대 뜻풀이)가 섞여 있다.
- seed 하나로 한 번 실행했다. 문항별 비교로 방향은 확인했지만 신뢰구간은 계산하지 않았다.

## 재현

```bash
make fetch && make index      # Apple Silicon 기준 약 10분
make ablation                 # LLM 호출 없음. rerank 포함 약 20분(MPS). 일부만: python -m kdr.eval --ablation --mode hybrid_rerank
ollama pull qwen3:8b && make eval          # 로컬 8B 모델로 약 1시간
python -m kdr.eval --arm naive_rerank --arm graph_rerank --workers 4   # rerank 팔. Ollama 는 OLLAMA_NUM_PARALLEL=4
LLM_PROVIDER=openai make eval             # OpenAI 호환 엔드포인트로 같은 200문항
```

결과는 `results/{model}/{arm}.jsonl`(문항별)과 `summary.md`에 남는다. jsonl에는 KorQuAD 원문이 들어가므로 저장소에는 포함하지 않는다. `python -m kdr.eval --rescore results/qwen3-8b`로 저장된 답변을 다시 채점할 수 있다.
